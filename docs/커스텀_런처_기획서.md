# 커스텀 모드 런처 + 모드 서버 구축 기획서

- **문서 버전:** v1.0 (기술 검증 반영본)
- **작성일:** 2026-06-09 (KST)
- **상태:** 기획 확정 대기 (§13 결정 필요 항목 잠금 후 착수)
- **검증 근거:** 7개 기술영역 병렬 웹 리서치 + 교차검증 (CmlLib.Core / MS 인증체인 / packwiz / Fabric / Avalonia 패키징 / 코드서명·공증 / 통합 연결부). 본 문서의 버전·API·정책 단정은 모두 출처 검증을 거쳤으며, "must-verify" 표시 항목은 구현 착수 시 재확인 대상이다.

## 1. 배경 및 목적

친구들과 함께 즐길 모드 적용 마인크래프트 서버를 운영하되, **비개발자도 클릭 한 번으로 접속**할 수 있는 환경을 만든다. 단발성이 아니라 **장기 운영**을 전제로 하며, 다음을 핵심 가치로 둔다.

- **무설치 부담:** 사용자는 런처만 한 번 설치하면 모드·런타임·서버 등록이 자동으로 끝난다.
- **지속 확장:** 모드를 계속 추가하고 인원을 늘려도, 런처를 매번 다시 배포하지 않는다.
- **신뢰성:** 백신을 끄게 하거나 출처 불명 실행을 강요하지 않는, 정상적으로 서명·배포되는 런처.

> 참고 사례(ICY Online)는 "백신을 해제하고 다운로드하라"고 안내하는데, 이는 정상 배포가 하지 않는 행위이며 악성코드 유포와 외형상 구분되지 않는다. **본 프로젝트는 이 패턴을 명시적으로 배제한다.**

> **현실 보정 (v1.0):** "백신/경고 0회"는 Windows에서 완전 달성이 어렵다. EV 인증서는 2024년부터 SmartScreen 즉시 우회 기능이 제거됐고, 평판(reputation)은 "수 주 + 광범위 사용자의 수백 건 클린 설치"로만 쌓이는데 지인 한정 배포는 그 규모에 도달하지 못한다. 따라서 Windows는 "서명으로 게시자명 표시 + 1회성 'More info → Run anyway' 안내"가 현실적 목표다. **반면 macOS는 Gatekeeper가 미공증 앱을 하드 차단**하므로 Apple 공증이 사실상 필수다 (§7, §13-C 참조).

## 2. 목표 (Goals) / 비목표 (Non-Goals)

**목표**
- 비개발자 친구가 런처 설치 → 로그인 → Play 만으로 접속.
- 모드팩을 단일 정의로 관리하고, 서버·클라이언트가 항상 같은 버전을 공유.
- 모드 추가/교체 시 런처 재배포 없이 자동 동기화.
- Windows / macOS 동시 지원 (Apple Silicon 포함).

**비목표 (현 단계 제외)**
- 공개 배포·다수 비인가 사용자 대상 서비스 (지인 중심 운영).
- 자체 모드 개발 (기성 모드 조합만 사용).
- 모바일/콘솔 지원.

## 4. 시스템 아키텍처

### 4.1 단일 진실 공급원 (Single Source of Truth)

모드팩 정의를 **한 곳에서만** 관리하고, 서버와 런처가 모두 이를 바라본다.

```
        [ 모드팩 정의 = packwiz (TOML, git 관리) ]
        호스팅: GitHub Pages (pack.toml URL)
                          │
        ┌─────────────────┴──────────────────┐
   [ 서버 ]                              [ 커스텀 런처 ]
   Fabric 서버                           실행 시마다 (엄격한 순서):
   packwiz-installer -s server      →     1) 자체 업데이트 (Velopack)
   = server + both 모드 설치              2) MS device-code 로그인 (silent→fallback)
                                          3) CmlLib Java 설치 → JavaPath 확보
                                          4) packwiz 동기화 -s client (위 JavaPath 재사용)
                                          5) CmlLib Fabric 설치 + 게임 install
                                          6) 서버 자동접속(ServerIp) 후 실행
```

**모드 변경 흐름:** packwiz 팩 수정 → `packwiz refresh` → git push → 서버는 재시작(또는 cron/systemd로 bootstrap 재실행) 시, 클라이언트는 다음 실행 시 변경분만 자동 동기화. **런처 바이너리는 건드리지 않는다.**

> **v1.0 핵심 보정 — 실행 순서 불변식(invariant):** 3단계(Java 설치)가 4단계(packwiz)보다 **반드시 먼저** 와야 한다. packwiz-installer-bootstrap.jar는 JRE가 있어야 실행되는데, 그 JRE를 CmlLib가 설치한다(닭-달걀 문제). MultiMC의 `$INST_JAVA` 패턴처럼 **CmlLib가 확보한 java 실행파일 경로를 packwiz bootstrap에 그대로 넘긴다.** 자세한 불변식은 구현계획 문서 §실행 순서 참조.

### 4.2 모드 분리 정책 (side)

모든 모드는 packwiz 정의에서 `side` 값을 가진다 (packwiz-installer 소스 `Side.kt`로 검증).

| side | 대상 | 설치 위치 | 예시 |
|------|------|-----------|------|
| both | 콘텐츠 모드(블록·아이템·차원) + 공유 라이브러리 | 서버 + 클라 동일 버전 | **Fabric API**, 콘텐츠 모드 |
| client | 화면·성능·편의 | 클라 전용 | Sodium, Iris, 미니맵, Litematica |
| server | 서버 유틸 | 서버 전용 | LuckPerms |

단일 팩에서 `-s client` / `-s server`로 각자 자기 몫만 받는다(`both`는 양쪽 모두 받음). **버전 불일치로 인한 접속 거부가 구조적으로 방지**된다.

> **흔한 함정 (검증됨):** ① **Fabric API는 반드시 `side=both`** — 서버가 필요로 하는 콘텐츠를 담고 있어 client-only로 잘못 태깅하면 서버가 깨진다. ② packwiz의 Modrinth/CurseForge 메타데이터 자동 side 감지는 불완전하므로 `packwiz add` 후 각 `.pw.toml`의 side를 **수동 감사**해야 한다. ③ 같은 폴더에서 `-s` 값을 바꾸면 `cachedSide` 불일치로 **전체 재다운로드**가 발생 — 런처는 항상 `-s client` + 동일 `--pack-folder` 고정.

### 4.3 런처 실행 시퀀스 (v1.0 정정 — 순서 의존성 반영)

1. **자체 업데이트** (Velopack `VelopackApp.Build().Run()`는 `Main` **최상단 첫 줄**) → 필요 시 적용 후 재시작.
2. **Microsoft 로그인** — 캐시 토큰으로 silent 시도 → 실패 시 device-code 인터랙티브 fallback. `user_code` + `verification_uri`를 Avalonia UI에 표시(WebView2 불필요). **인증 성공 직후 Minecraft Java 소유권/프로필을 검증**해, 미구매 계정(엔타이틀먼트 404)·XSTS 오류(미성년/지역/밴)를 generic error가 아닌 **전용 한국어 메시지 경로**로 분기.
3. **CmlLib로 Java 설치/검증** → 확보된 `JavaPath`를 변수에 캐싱 (Apple Silicon은 arm64 JRE 확인).
4. `packwiz-installer-bootstrap.jar -g -s client <pack URL>` 를 **3에서 확보한 java로** 실행 → 모드 증분 동기화.
5. CmlLib `FabricInstaller`로 Fabric 로더 설치 → `InstallAndBuildProcessAsync(fabricVersionId, option)` (해시 검증).
6. `MLaunchOption.ServerIp/ServerPort` 주입(또는 `servers.dat` 주입) 후 게임 프로세스 실행. macOS는 `DockName` 설정 필수.

> **실패 경로 우선 설계 (Codex H1 반영):** 위 1~6의 각 단계는 "성공"만이 아니라 **명시적 실패 게이트**를 갖는다 — Java 다운로드 실패·디스크 풀, packwiz CDN 404/네트워크 부분 실패·pack.toml stale, Fabric 메타 실패, 토큰 만료, **서버 다운(접속 전 ping 안내)**, 자체업데이트 소스 부재(graceful skip 후 진행). 모든 단계는 try/그룹 + exit-code 게이트로 감싸고 실패 시 비개발자용 한국어 재시도/도움 UI를 띄운다(구현계획 §4·M1-8). 또한 설치(3~5) 도중 토큰이 만료될 수 있으므로 **`proc.Start()` 직전 세션 재검증/refresh**를 둔다(Codex M4).

## 6. 크로스플랫폼(특히 macOS) 고려사항

- **UI는 반드시 Avalonia.** WPF/WinForms는 macOS 미동작. 첫 줄부터 Avalonia.
- **로그인은 device-code 플로우.** Windows 전용 WebView2 로그인 창 의존 배제. device-code의 `user_code`/`verification_uri`만 UI에 띄우면 양 OS 동일 동작.
- **Apple Silicon (arm64):** MC 26.1(=Java 25)은 arm64 네이티브(LWJGL3 arm64 + arm64 JRE) 지원. Mojang `java-runtime` 매니페스트의 `mac-os-arm64` 키가 26.1용 Java 25 런타임을 제공하므로 CmlLib가 자동 해결. 네이티브 arm64는 Rosetta 대비 체감 성능이 크게 높다(수치는 환경의존). 착수 시 26.1.2의 mac-os-arm64 런타임 실재를 실기 검증(M2-5).
- **macOS 창 포커스 함정 (MEDIUM):** macOS에서 `MLaunchOption.DockName`(과 `DockIcon`) 미설정 시 실행된 MC 창의 Dock 인식/포커스 문제가 **발생할 수 있다** — 비개발자에겐 "멈춤"으로 보인다. CmlLib 공식 Common-Errors 문서가 지적. **DockName 설정을 필수 기본값으로** 두되, macOS arm64 실기에서 반드시 재현 검증.
- **모드 자체는 OS 무관**(Java 바이트코드)이라 동일 모드가 양 OS에서 동작.
- **쓰기 데이터 위치 불변식 (검증된 함정):** 게임 디렉토리·`servers.dat`·packwiz mods·MSAL 토큰 캐시·Velopack staging은 **반드시 서명된 앱 번들 바깥**(`%APPDATA%` / `~/Library/Application Support`)에 둔다. 번들 내부에 쓰면 codesign 서명·staple이 깨져 Gatekeeper 차단 + 자체 업데이트 실패.

### 6.4 서버 접속 방식 결정 (R3)

| 방식 | 동작 | 장점 | 단점 |
|------|------|------|------|
| **`MLaunchOption.ServerIp` (권장)** | 실행 즉시 해당 서버로 자동 접속 | 파일 쓰기 없음·fNbt 불필요·"원클릭" 그 자체 | 멀티플레이 목록엔 안 남음 |
| `servers.dat` 주입 (fNbt) | 멀티 목록에 서버가 미리 저장됨 | 일반 멀티 메뉴에서도 보임 | NBT 비압축 저장(`NbtCompression.None`) 필수, 백업·merge 필요(GZip 저장 시 목록 전체 소실) |

> **권장:** "클릭 한 번 접속"이 핵심 가치이므로 **`ServerIp` 자동접속을 1차 경로**로 채택하고 fNbt 의존을 제거. 목록 보존이 필요할 때만 servers.dat 주입을 보조로 추가하되 둘을 동시에 켜지 않는다(중복 항목 혼란).

## 7. 배포 전략 (v1.0 — 서명 현실 반영)

| 플랫폼 | 패키징 | 서명/검증 | 현실 평가 |
|--------|--------|-----------|-----------|
| Windows | Velopack(`vpk pack`) → 설치/포터블 + 자체업데이트 | Authenticode (OV; **EV 불필요**) 또는 미서명 | 서명해도 SmartScreen 첫 실행 경고는 **저배포량에선 사라지지 않음**. 게시자명만 표시됨 |
| macOS | Velopack(`vpk pack`, `.app`+`.pkg`/`.zip`, arm64) | Developer ID + hardened runtime + **notarytool 공증** + staple | Gatekeeper **하드 차단** → 공증 사실상 필수 |

**원칙 (검증 반영)**
- **EV 인증서 구매 금지** — 커널 드라이버가 아니면 SmartScreen 이점 0. (2024년 즉시우회 폐지)
- **UPX 패킹 금지** — AV 휴리스틱 1순위 트리거(서명돼 있어도 오탐). 크기 축소는 `PublishTrimmed`/`ReadyToRun`/`PublishSingleFile` 압축 사용.
- macOS는 **`--deep` 미사용**(Apple TN2206이 "권장 안 함"으로 명시 — 프로젝트 정책상 배제). 중첩 `.dylib`을 잘못 서명/누락하기 쉬움. **inside-out**(깊은 것부터 개별 서명 → 번들 마지막)으로 서명. Velopack 사용 시 자동 처리.
- macOS는 **`net*-macos` TFM 금지**(net10.0-macos 등) — MonoBundle 경로로 빠져 공증 실패. 평범한 RID(`-r osx-arm64`) self-contained로 게시.
- 로그인은 항상 공식 OAuth(device-code)만. 아이디/비밀번호 직접 수집 폼 금지.
- 오탐 발생 시 WDSI(`microsoft.com/wdsi/filesubmission`) "Software developer – false positive"로 신고. **사용자에게 백신 해제 요구 금지.**

> **인증서/CI 함정 (Korea 위치 반영):** Azure Artifact(Trusted) Signing 개인 개발자 티어(~$10/mo, 토큰 불요)는 **US/Canada 한정**이라 한국 소유자는 이용 불가 가능성이 높다(가입 시 확인 필요). 대안은 (a) OV 인증서 + 클라우드 HSM(eSigner/KeyLocker)로 CI 서명 — USB 토큰은 호스티드 러너에서 사용 불가, (b) 미서명 배포 + 1회성 클릭스루 안내. 지인 한정이면 (b)가 최저비용·최저후회 (§13-D).

## 8. 서버 운영 계획 (v1.0 — 운영 라이프사이클 보강)

- **호스팅:** 초기엔 자체 PC 가능하나 인원·모드 증가 시 VPS/전문 호스팅 권장(모드 서버 RAM 4GB+ 쉽게 초과).
- **모드 동기화:** 클라이언트와 동일 packwiz 팩을 `-s server`로 적용. 팩 push가 서버 박스에 닿는 방식(cron/systemd로 bootstrap 재실행 또는 수동)을 명시적으로 정한다.
- **운영 기능(플러그인 불가 → 모드로 대체):** Fabric은 Bukkit/Spigot/Paper 플러그인 미지원. **LuckPerms(Fabric 빌드)**=권한/그룹, **Open Parties and Claims** 또는 **FTB Chunks(Fabric)**=땅 클레임/보호(둘 다 LuckPerms 연동).
- **JVM 튜닝:** Aikar's flags(G1GC) — 4GB 기준 `-Xms4G -Xmx4G` + G1 플래그 세트, `Xms==Xmx` 유지, 콘텐츠 많으면 6~8G.
- **server.properties:** 실 MS 인증 사용이므로 `online-mode=true`. `view-distance`는 소규모 서버 RAM 절약을 위해 8~10.
- **운영 라이프사이클 (신규):** 월드/region **백업**, 서버 **자동 재시작/크래시 복구**, **RCON/콘솔 관리**, 팩 push의 서버 자동 반영 경로를 운영 항목으로 포함(장기 운영 전제).

## 13. 결정 필요 항목 (빌드 착수 전 잠금 — Decision Lock)

> 아래 A~E는 계획 전체에 연쇄(cascade)하므로 UI 구현 전에 확정해야 한다. **AI가 대신 정할 수 없는 사용자 영역**이며, 각 항목에 권장안을 제시한다.

- **A. 구체 모드 목록 + side 분류 (✅ 확정)** — 사용자 제공 목록을 검증·큐레이션 완료. 전부 성능/QoL/시각/바닐라+ 계열이라 **Fabric 확정**(기술·자동화 모드 없음 → NeoForge 불요). 최종 모드셋·side·packwiz 명령은 **[모드구성.md](모드구성.md)** 참조.
- **B. 마인크래프트 버전 고정 (✅ 확정)** — **26.1.2** (현재 최신 안정판, 연도 기반 버전). 사용자 "최대한 최신" 의도 + 요청 모드 전부 26.1.2 stable 정렬 + 한글 IME 네이티브 지원을 동시 충족. 동결, 26.2는 생태계 성숙 후 의도적 bump. `pack.toml`이 MC+Fabric loader+API 버전의 SoT.
- **C. macOS 배포 여부** — Mac 친구가 있으면 Apple Developer $99/yr + 공증 필수(Gatekeeper 하드 차단). *권장: 가입·공증 채택.*
- **D. Windows 서명 경로** — *권장: 지인 한정이므로 미서명 + "More info→Run anyway" 1회 안내*(서명이 경고를 못 없앰). 게시자명 표시가 꼭 필요하면 OV+클라우드HSM. Azure 개인티어는 한국 가용성 확인 필요.
- **E. 호스팅 토폴로지 + 모드리스트 공개 여부** — *권장: GitHub Pages=pack.toml, GitHub Releases=Velopack 피드.* 단 public 레포는 모드리스트가 공개되므로, 비공개가 중요하면 private 정적 호스트.
