## Medium / Low — CONFIRMED (즉시 수정 → 본 커밋 반영)

### ✅ FIXED — StreamWriter 핸들 누수 (medium) — `Services/CmlLibServices.cs:271-326`
3개 차원(security/logic/quality)이 **독립 수렴**한 NET-NEW 결함. `TryEnableGameLogCapture`가 game-*.log `StreamWriter`(AutoFlush)를 즉시 열지만 Dispose는 `proc.Exited` 핸들러에서만 일어남. 그런데 capture 부착 후 `ct.ThrowIfCancellationRequested()` 또는 `proc.Start()` 실패로 **프로세스가 시작되지 않으면 Exited가 영영 발화 안 함** → writer 파일핸들이 GC 파이널라이저까지 누수(Windows 파일락). 취소→재시도 반복 시 누적. S1 수정(packwiz 자식 kill)과 별개 경로.
- **수정**: `TryEnableGameLogCapture(proc, out StreamWriter? writer)` 로 writer 노출 → LaunchAsync의 시작실패/취소 catch 2곳에서 `captureWriter?.Dispose()`. 성공 경로는 기존대로 Exited가 Dispose.

### ✅ FIXED — 오해를 부르는 죽은 주석 (low) — `Services/ServerList.cs:64`
주석은 "동일 name+ip 중복 방지"라 설명하나, 실제 dedup(line 61)은 **host 한정**(name/port 미비교)이고 Insert(line 68)는 무조건 실행. 기능 영향 없으나 유지보수자 오인 유발.
- **수정**: 주석을 실제 동작(host 제거 후 맨앞 삽입, dedup 키=host)으로 정정.

## POST-1.0 DEFERRED (21건 — 실제이나 1.0 비차단; 근거와 함께 추적)

검증기가 "실제 결함이나 1.0 차단 아님(구조개선·EXT·테스트 보강·희귀 엣지)"으로 분류. 향후 개선 백로그.

**아키텍처/설계 (8, 전부 low)**
- VM이 `LaunchOrchestrator`/`OfficialLauncherInstaller`를 직접 `new()` — DI 부재로 VM 테스트 불가
- `OfficialLauncherInstaller`만 인터페이스 부재 — 4 launch 서비스와 추상화 비대칭
- `ViewLocator` 규약이 실제 View 네이밍과 불일치 — dead infra/latent trap
- `RamAdvisor.EffectiveMaxRamMb()`가 호출마다 `LauncherSettings.Load()` 디스크 I/O — 숨은 의존
- 단일 `_cts`를 PlayAsync/InstallToOfficialAsync 두 커맨드가 공유 — fragile shared state
- `ClientDefaults`가 static God-helper로 비대 (옵션/iris/servers.dat/마커/번역팩 정렬 응집)
- `LaunchOptions.Offline`/`IsOffline` 분기가 온라인 전용 전환 후에도 잔존 — dead 분기
- `HttpClient` 미해제 (저위험·앱수명 싱글턴 — severity none)

**로직/엣지 (5, low~medium)**
- (medium) `ClientDefaults` stale 정리가 file/ 엔트리 제거하나 apply-once 마커 유지 → packwiz 재다운로드 동일 팩 영구 미활성 가능 *(리소스팩 영역 — 실 런 검증 없이 미수정, 별도 추적)*
- `ServerList.HostOf`가 IPv6 리터럴/대괄호 주소를 마지막 ':' 기준 오파싱
- `ServerPing`가 선언 packet length(len)를 무시하고 소켓에서 직접 더 읽음(len 검증 실질 무효)
- `ClientDefaults`가 changed=true 시 빈 `incompatibleResourcePacks:` 라인 신규 삽입
- `servers.dat` 갱신이 매 실행 제거-후-맨앞삽입 → 사용자가 옮긴 순서/이름 덮어씀

**보안 (2, low)**
- `accounts.json`이 `Harden` 직전까지 기본 umask(world-readable) 노출되는 TOCTOU 창
- (위 ServerPing/IPv6도 보안 인접)

**테스트 보강 (6, low~medium)**
- (medium) `EnsureDefaultResourcePacks` 통합 동작 전체 미테스트 — 이번 세션 실버그 영역, 회귀 위험 최고
- (medium) Orchestrator 성공 경로(revalidate→launch→Running→non-null) 미테스트 — 구조적 테스트 불가(DI 부재)
- `Effective_ram_within_bounds`가 실 %APPDATA% settings.json 읽음 — 환경 의존 false-green
- 취소 테스트가 pre-cancel(첫 게이트)만 — 단계 사이 취소 전파 미커버
- `EnsureTranslationPackAtBottom` 회귀가 stale-cleanup 상호작용·중복 vanilla 미커버
- `LauncherSettings.Save` 원자적 교체(.tmp→Move)·손상 JSON 경로 미커버

## REJECTED (3 — 적대적 검증으로 오탐 확정)

- **OnStageUpdate HasError 무조건 덮어쓰기** (MainWindowViewModel) → 타이밍 추적상 도달 불가. ApplyAll 성공 업데이트는 게임 launch + WaitForExitAsync 한참 전에 드레인됨. 게임 콜백은 로그파일만 쓰고 progress.Report 미호출 → 크래시 에러는 실질 sticky. **오탐**.
- **HttpClient 다중 인스턴스 = 소켓 고갈 안티패턴** → 셋 다 앱수명 싱글턴(MS 권장 패턴), packwiz `using`은 Play당 최대 1회 occasional one-shot. 소켓 고갈 전제 거짓. **오탐**.
- **ConfigDrift가 원격 PackTomlUrl과 drift 미가드** → `modpack-pages.yml`이 `modpack/`을 byte-for-byte Pages 배포 → 로컬 커밋 파일이 곧 원격 SoT. 라이브 URL fetch는 flaky 안티패턴. **오탐**(substring 매칭 약점은 low-trivial).
