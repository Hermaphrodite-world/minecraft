## 0. 이 문서의 사용법

기획서가 "무엇을·왜"라면 본 문서는 "어떤 순서로·어떻게 검증하며"다. 핵심 3가지를 먼저 못박는다.

1. **Day-1 long-pole** = Azure 앱 등록 + Microsoft 승인 (외부 의존, 비차단 병렬화).
2. **실행 순서 불변식** (§4) = Java → packwiz → Fabric → launch. 어기면 클린 머신에서 깨진다.
3. **잠금 결정 5종** (기획서 §13 A~E) = 빌드 착수 전 사용자가 확정. 본 계획은 권장 기본값으로 진행하되, 확정 시 해당 마일스톤만 갱신.

## 2. 레포 토폴로지 (org: Hermaphrodite-world)

권장: **멀티 레포** (관심사 분리 — "모드 추가 = 팩 push, 런처 무수정" 보장).

| 레포 | 역할 | 공개 | 비고 |
|------|------|------|------|
| `launcher` | Avalonia/.NET 런처 소스 + GitHub Releases(Velopack 피드) | private 소스 / Release 자산은 다운로드 가능 | 런처 바이너리 배포처 |
| `modpack` | packwiz 팩(TOML) + GitHub Pages(`pack.toml`) | **공개 여부 = 결정 E** | public이면 모드리스트 노출 |
| `server` | 서버 구성(start 스크립트·server.properties·운영 모드 목록·백업 스크립트) — 월드 데이터는 제외(.gitignore) | private | 운영 IaC |
| (선택) `docs` | 친구용 설치 안내(클릭스루 포함)·운영 런북 | private | org 내부 |

- device-code 콜백 객체 속성명 (`dc.Message` vs `dc.VerificationUrl`/`dc.UserCode`).

## 4. 런처 실행 순서 불변식 (구현 핵심)

> 이 순서는 **선호가 아니라 하드 요구**다. 각 화살표는 의존성이다.

```
(1) VelopackApp.Build().Run()        ← Main() 최상단 첫 줄 (UI/기타 init 이전, 강제)
        │  업데이트 있으면 적용+재시작
        ▼
(2) Auth: silent(캐시 토큰) → 실패 시 device-code fallback
        │  MSession 확보 (UI에 user_code/verification_uri 표시)
        ▼
(3) CmlLib Java 설치/검증 → JavaPath 캐싱   ← arm64 JRE 확인(macOS)
        │  (4)가 이 JavaPath를 재사용 — 닭/달걀 해소
        ▼
(4) packwiz bootstrap: <JavaPath> -jar packwiz-installer-bootstrap.jar -g -s client <PACK_TOML_URL>
        │  PACK_TOML_URL = 정확히 `pack.toml`로 끝나는 전체 URL (예: https://org.github.io/modpack/pack.toml)
        │  ※ 베이스 URL + "/pack.toml" 식 문자열 결합 금지 — 이중 경로(pack.toml/pack.toml) 버그 방지(Codex M3)
        │  --pack-folder = 외부 데이터 디렉토리(번들 밖) 고정, -s client 고정
        ▼
(5) CmlLib FabricInstaller → InstallAndBuildProcessAsync(fabricVersionId, option)  ← 해시 검증
        │
        ▼
(5.5) 세션 재검증/refresh: (2)~(5) 동안 토큰 만료 가능 → MLaunchOption 구성 직전 MSession validate (Codex M4)
        │
        ▼
(6) (서버 ping 확인) → MLaunchOption { Session, ServerIp, ServerPort, MaximumRamMb, DockName(macOS) } → proc.Start()
```

**각 단계 실패 게이트 (Codex H1 — 비개발자 1-클릭 흐름 보호):**
- 모든 단계를 try/그룹 + exit-code 게이트로 감싸고, 실패 시 한국어 재시도/도움 UI.
- (1) 업데이트 소스 부재/도달 불가(아직 Release 0건 등) → **graceful skip 후 진행**(Codex M7).
- (2) 인증 직후 **소유권/프로필 검증** → 미구매(404)/XSTS(미성년·지역·밴) 전용 메시지(Codex H2).
- (3) Java 다운로드 실패·디스크 풀 → 재시도/공간 안내.
- (4) packwiz CDN 404·네트워크 부분 실패·pack.toml stale(캐시) → 재시도+backoff(매 실행 재동기화라 self-healing).
- (5) Fabric 메타 실패 → 재시도.
- (6) **서버 다운**: ServerIp 자동접속은 MC가 "연결 실패"를 띄우므로, 접속 전 서버 ping으로 사전 안내(또는 실패 메시지 친화화).

**불변식 위반 시 증상(검증된 것):**
- (3)→(4) 역전: 클린 머신에서 Java 없어 packwiz 실패.
- (1)이 첫 줄 아님: Velopack 원자적 교체/재시작이 UI와 race → 손상 가능.
- 번들 내부에 (4)(6) 데이터 쓰기: codesign/staple 깨짐 → Gatekeeper 차단 + 자체업데이트 실패.
- (5.5) 누락: 긴 설치 후 (6)에서 만료 토큰으로 늦게 실패.

## 6. CI/CD 설계 (GitHub Actions)

```
matrix:
  - windows-latest : dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true
                     -p:IncludeNativeLibrariesForSelfExtract=true → vpk pack (win)
                     [결정 D=서명 시 azure/trusted-signing-action 또는 eSigner; 미서명이면 생략]
  - macos-14       : dotnet publish -r osx-arm64 --self-contained (single-file 아님)
                     → vpk pack (mac) --signAppIdentity/--signInstallIdentity/--notaryProfile
                     (Developer ID .p12 base64 secret → security import + set-key-partition-list)
                     (notarytool store-credentials, app-specific password)
release: vpk upload github  (양 OS 자산을 동일 GitHub Release로)
```

**CI 함정(검증):**
- macOS notarytool은 macOS 러너에서만. `--wait`는 재시도 안 하므로 submit 스텝에 retry 래핑.
- `security set-key-partition-list`로 codesign 비대화형 프롬프트 회피(필수).
- USB 토큰 인증서는 호스티드 러너 불가 → 서명 시 클라우드 HSM/eSigner.
- 서명은 **빌드 최종 스텝**. 서명 후 바이트 변경(재압축 등) 금지.

## 9. 결론 / 종합 판정

선택 스택(CmlLib.Core 4.0.6 + Auth.Microsoft 3.3.1 + packwiz + Fabric + Avalonia 11.3/.NET 10 + Velopack 1.2)은 **일관되고 목표에 부합**한다 (런처 통합 구현·빌드 완료). 기술 리스크는 LOW~MEDIUM이며, **지배적 리스크는 구현이 아니라 외부·결정 게이트**(모드/로더 선택, Azure 승인, macOS 공증)다. 따라서 코딩 착수 전:

1. **모드 목록 → 로더(A) + MC 버전(B)** 잠금,
2. **Azure 앱 + MS 승인 day-1 착수**,
3. **외부 데이터 디렉토리 + 실행 순서 불변식**을 설계 원칙으로 고정

— 이 셋을 front-load하면 나머지는 병렬로 안정적으로 진행 가능하다. 정확한 API 시그니처(FabricInstaller v4, MSAL 콜백)와 한국 위치 의존 Windows 서명 분기는 "착수 시 재확인" 항목으로 다룬다.
